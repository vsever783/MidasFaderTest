# MidasFader — пульт Midas Pro2 с Android

Приложение для удалённого управления консолью Midas Pro2 по протоколу UDP/OSC.
Реверс-инжиниринг протокола выполнен через захват трафика официального
приложения Mixtender 2 (Wireshark) + сверку со сторонним датасетом
midas-pro-mcp-server (см. раздел "Источники данных" ниже).

Пакет: `com.example.midasfadercontrol`. Один APK, два режима запуска
(инженер / монитор), выбираются на стартовом экране (`RoleSelectActivity`).

---

## Архитектура

### Ключевые файлы
- `RoleSelectActivity.kt` — стартовый экран выбора режима
- `MainActivity.kt` — вся логика обоих режимов (инженер + монитор), самый
  большой файл проекта
- `Pro2Commands.kt` — все OSC-адреса и функции кодирования команд
- `OscUtil.kt` — низкоуровневое кодирование/декодирование OSC
- `RotaryKnobView.kt` — кастомная поворотная ручка
- `TransferCurveView.kt` — график передаточной функции COMP/GATE
- `EqCurveView.kt` — интерактивный график параметрического EQ

### Сеть и протокол
- Пульт: порт **10000**. Приложение: локальный порт **10001** (один порт
  на оба режима — раньше были раздельные, объединили, когда выяснилось,
  что пульт различает клиентов **только по IP**, не по порту)
- Push-модель через `/batchsubscribe`: приложение подписывается на
  человекочитаемый путь (`/enPPCRotaryMessage/enVirtualMicInputs/enFaderLevel`
  и т.д.), пульт присваивает короткий числовой хендл (`/301b374f0`) и потом
  шлёт обновления именно на этот хендл. Прямой GET почти никогда не
  работает надёжно — путь только через подписку
- `/renew` каждые ~3 сек обязателен, иначе пульт отключает подписку по
  таймауту
- **Байт-порядок:** push-значения — little-endian; SET-команды — обычный
  OSC big-endian
- **Переключатели (mute/solo/comp in/фаза/фильтры и т.д.)** — это
  TOGGLE-параметры: любой полученный пакет переключает состояние на
  пульте, независимо от значения. Приложение **всегда** шлёт "включить"
  (1), никогда явно 0 — иначе пульт часть пакетов игнорирует (баг, который
  ловили и чинили несколько раз)
- **Метры** — 1 байт, диапазон 0-255 (не 0-127, как предполагалось раньше)

## Статус функций

### ✅ Полностью реализовано и подтверждено
- 56 входных каналов: фейдер/mute/solo/имя/цвет/метр/панорама/48V/фаза/
  gain/gain trim/HP-LP фильтры/input delay
- Компрессор и Gate: полный набор параметров + графики передаточной
  функции + GR и detector-метры
- EQ (4 полосы: BASS/LOW-MID/MID-HIGH/TREBLE) — интерактивный график с
  перетаскиванием точек, свои диапазоны частот на полосу, форма BELL/SHELF
  для BASS и TREBLE
- Sends: горизонтальная таблица на 16 aux-шин, PRE/POST + ON/OFF на посыл
- Master (3), Aux Returns (8), Aux-шины (16), VCA-группы (8) — фейдер/
  mute/solo/имя/цвет
- Solo B — для обычных каналов и master/aux returns/aux-шин (⚠️ по
  просьбе пользователя сейчас **скрыт** из UI, код остался, легко вернуть)
- Мониторный режим: список aux-шин → горизонтальный вид фейдеров/посылов
  на 56 каналов

### ⚠️ Реализовано, но требует проверки/данных
- **EQ форма (bell/shelf)** — переключается только между 2 состояниями,
  по заметкам пользователя на пульте их 4 (parametric/bright/classic/soft).
  Ждём отдельную информацию от пользователя
- **Режим компрессора/gate** (`enCompDetectorMode`/`enGateMode`) —
  подтверждено реальным захватом, отображается как число ("MODE: N"),
  **только чтение** — не знаем формат SET-команды (в захвате смена
  происходила прямо на экране пульта, не через iPad)
- **LINK** (стерео-пара каналов) — реализован по адресу `enRoutingLinked`
  из стороннего датасета, **не работает** на реальном пульте. Возможно,
  нужен другой адрес (`enConfigPairingState`, подтверждён для master/
  aux-шин, но не для обычных каналов)
- **VCA-назначение каналов** — работает "условно" (по словам
  пользователя), структура взята из стороннего датасета, не из
  собственного захвата

### ❌ Не реализовано / нерешённые вопросы
- **Метры в мониторном режиме** — экран с 56 фейдерами после выбора шины
  никогда не имел UI для метров вообще (не баг, а недостающая функция)
- **Патчинг физических входов** — подтверждено, что данные передаются по
  OSC (числовые хендлы, не человекочитаемые пути), но конкретный параметр
  назначения маршрута среди них не найден. Нужна короткая прицельная
  запись с точным моментом одного действия патчинга
- **Mute-группы** — структура ясна из стороннего датасета (аналогична
  VCA), не реализовано
- **Main Outs** — 8 позиций (3 с полной обработкой) — не реализовано
- **31-полосный графический EQ** — не реализовано, отдельная большая
  задача
- **SAFE** (защита канала от recall сцены) — адреса найдены в стороннем
  датасете, не реализовано

## Технические уроки (чтобы не наступать на грабли повторно)

1. **Массовая подписка при подключении убивает пульт.** Раньше слали
   ~1700+ подписок одним потоком без пауз — перегружало пульт настолько,
   что сбоил даже официальный Mixtender на другом устройстве. Сейчас:
   пауза 2мс между пакетами + одно пакетное переключение на главный поток
   вместо тысячи отдельных + большая часть параметров переведена на
   ленивую подписку (только при реальном открытии вкладки)
2. **Мониторный режим не должен наследовать полную подписку инженерского.**
   Ему нужно только ~64 параметра (aux-шины), не ~800
3. **Блокирующий приём UDP-пакетов замораживает метры.** Раньше
   `withContext(Dispatchers.Main)` в цикле приёма ждал завершения отрисовки
   перед чтением следующего пакета — при таком объёме метры "зависали".
   Исправлено на fire-and-forget диспетчеризацию
4. **Поворот экрана полностью пересоздаёт Activity** (нет
   `android:configChanges` в манифесте, сознательно не трогали). Все
   данные, которые должны пережить поворот, обязаны храниться в
   `ConnectionHolder` (singleton-объект), а не как обычные поля
   `MainActivity` — иначе сбрасываются в начальное состояние. Так
   ловили и чинили: `openDetailChannel`, теперь ещё и `openDetailTabName`
5. **`str_replace` при редактировании иногда молча теряет контент** при
   опечатке в имени параметра инструмента — привычка проверять `grep`
   сразу после каждой правки спасла несколько раз от потери рабочего кода
6. **Сторонние датасеты (midas-pro-mcp-server) полезны, но не заменяют
   реальный захват.** EQ Shape, например, подтверждён нашим собственным
   захватом, но отсутствует в том датасете целиком — наши данные точнее
   для конкретного экземпляра пульта

## Источники данных

- Основной: захват трафика официального Mixtender 2 через Wireshark
  (наиболее надёжный источник — всё, что подтверждено им, помечено
  "ПОДТВЕРЖДЕНО реальным захватом" в комментариях кода)
- Вспомогательный: `muffeeee/midas-pro-series-osc-commands` (GitHub) —
  список ~3900 команд, реверс-инжиниринг brute-force перебором на живом
  пульте
- Вспомогательный: `MyronKoch-dev/midas-pro-mcp-server` — MCP-обёртка над
  тем же датасетом muffeeee, плюс отдельный файл `pro-series-internal-
  fx-parameters-endpoints.json` (700 команд внутренних FX-параметров, не
  разбирали)
- Всё, что взято НЕ из собственного захвата, помечено в коде как "НЕ
  подтверждено реальным захватом" — использовать эти функции стоит с
  осторожностью на реальном шоу

## Известные ограничения по данным

Ни для одного параметра нет подтверждённой формулы перевода "сырое
значение ручки 0.00-1.00" → точные единицы (Гц/дБ/мс), КРОМЕ:
- Порог/атака/релиз компрессора (есть точки привязки в списке команд)
- Диапазоны частот EQ по полосам (сняты с фото экрана пульта +
  подтверждены заметками при тестировании)
- WIDTH диапазон EQ (0.1-3.0, линейная интерполяция — форма зависимости
  не подтверждена)

Все графики (COMP/GATE передаточная функция, EQ) — иллюстративные:
корректное направление и форма, но не лабораторно точные.
