# MidasFader — пульт Midas Pro2 с Android

Приложение для удалённого управления консолью Midas Pro2 по протоколу UDP/OSC.
Реверс-инжиниринг протокола выполнен через захват трафика официального
приложения Mixtender 2 (Wireshark) + сверку со сторонним датасетом
midas-pro-mcp-server (см. раздел "Источники данных" ниже).

Пакет: `com.example.midasfadercontrol`. Один APK, два режима запуска
(инженер / монитор), выбираются на стартовом экране (`RoleSelectActivity`).

## Архитектура

### Ключевые файлы
- `RoleSelectActivity.kt` — стартовый экран выбора режима
- `MainActivity.kt` — класс активности (оба режима, инженер + монитор):
  UI-сборка полос, детальный экран канала, lifecycle. **Крупный рефакторинг
  в процессе** — файл был 4712 строк, сейчас ~3850, часть логики вынесена
  в отдельные файлы (см. ниже). Kotlin не позволяет разбить один класс на
  несколько файлов напрямую — вынесенные функции сделаны extension-функциями
  на `MainActivity`, что потребовало сделать некоторые поля/функции класса
  `internal` вместо `private` (только видимость на этапе компиляции,
  поведение не меняется)
- `MainActivityNetwork.kt` — сетевой/протокольный слой (подключение, приём/
  передача UDP, все функции `subscribe*`, `handleIncomingMessage`, `sendRaw*`)
- `Models.kt` — перечисления и модели данных (`ParamKind`, `StripMode`,
  `Subscription`, `ChannelData`, `MasterData`, `AuxReturnData`, `AuxBusData`,
  `VcaData`, `MainOutData`)
- `ConnectionHolder.kt` — singleton-объект, хранящий состояние подключения
  между поворотами экрана (Android по умолчанию полностью пересоздаёт
  Activity при повороте - без этого объекта пришлось бы переподключаться
  заново)
- `Pro2Commands.kt` — все OSC-адреса и функции кодирования команд
- `OscUtil.kt` — низкоуровневое кодирование/декодирование OSC
- `RotaryKnobView.kt` — кастомная поворотная ручка
- `TransferCurveView.kt` — график передаточной функции COMP/GATE
- `EqCurveView.kt` — интерактивный график параметрического EQ

**Следующие кандидаты на вынос** (не сделано пока): обработчики push-значений
(`handle*SubscribedValue`, `update*Ui` — сильное дублирование логики между
master/aux returns/aux-шин/VCA/Main Outs, стоит ещё и обобщить, не только
вынести), UI-сборка полос (`build*Strips`), детальный экран канала.

### Сеть и протокол
- Пульт: порт **10000**. Приложение: локальный порт **10001** (один порт
  на оба режима — раньше были раздельные, объединили, когда выяснилось,
  что пульт различает клиентов **только по IP**, не по порту)
- Push-модель через `/batchsubscribe`: приложение подписывается на
  человекочитаемый путь (`/enPPCRotaryMessage/enVirtualMicInputs/enFaderLevel`
  и т.д.), пульт присваивает короткий числовой хендл (`/301b374f0`) и потом
  шлёт обновления именно на этот хендл. Прямой GET почти никогда не
  работает надёжно — путь только через подписку
- `/renew` каждые ~3 сек обязателен, иначе пульт отключает подписку по
  таймауту
- **Байт-порядок:** push-значения — little-endian; SET-команды — обычный
  OSC big-endian
- **Переключатели (mute/solo/comp in/фаза/фильтры и т.д.)** — это
  TOGGLE-параметры: любой полученный пакет переключает состояние на
  пульте, независимо от значения. Приложение **всегда** шлёт "включить"
  (1), никогда явно 0 — иначе пульт часть пакетов игнорирует
- **Метры** — 1 байт, диапазон 0-255

## Статус функций

### ✅ Полностью реализовано и подтверждено
- 56 входных каналов: фейдер/mute/solo/имя/цвет/метр/панорама/48V/фаза/
  gain/gain trim/HP-LP фильтры/input delay
- Компрессор и Gate: полный набор параметров + графики передаточной
  функции + GR и detector-метры
- EQ (4 полосы) — интерактивный график с перетаскиванием точек, свои
  диапазоны частот на полосу, форма BELL/SHELF для BASS и TREBLE
- Sends: горизонтальная таблица на 16 aux-шин, PRE/POST + ON/OFF на посыл
- Master (3), Aux Returns (8), Aux-шины (16), VCA-группы (8), **Main Outs
  (8, базовая полоса — fader/mute/solo/имя/цвет/метр, без EQ/компрессора)**
- Мониторный режим: список aux-шин → горизонтальный вид фейдеров/посылов
  на 56 каналов (облегчённая подписка, ~64 параметра вместо ~800)

### ⚠️ Реализовано, но требует проверки/данных
- **EQ форма (bell/shelf)** — только 2 состояния, по заметкам пользователя
  на пульте их 4 (parametric/bright/classic/soft)
- **Режим компрессора/gate** — только чтение, отображается числом
- **LINK** — не работает на реальном пульте, возможно нужен другой адрес
  (`enConfigPairingState`)
- **VCA-назначение каналов** — работает условно, структура из стороннего
  датасета

### ❌ Не реализовано
- Метры в мониторном режиме (экран с 56 фейдерами)
- Патчинг физических входов (данные по OSC есть, конкретный параметр не найден)
- Mute-группы, SAFE, 31-полосный графический EQ
- Main Outs: 6-полосный EQ + расширенный компрессор (есть только базовая полоса)
- Внутренние FX-параметры (700 команд, отдельный файл, не разбирали)

## Технические уроки

1. **Массовая подписка при подключении убивает пульт.** Решено: пауза 2мс
   между пакетами + пакетная регистрация вместо поштучной + большая часть
   параметров переведена на ленивую подписку (по факту открытия вкладки)
2. **Мониторный режим не должен наследовать полную подписку инженерского**
3. **Блокирующий приём UDP-пакетов замораживает метры** — исправлено на
   fire-and-forget диспетчеризацию вместо `withContext` внутри цикла приёма
4. **Поворот экрана полностью пересоздаёт Activity.** Всё, что должно
   пережить поворот — только через `ConnectionHolder`, не как обычные поля
   `MainActivity`
5. **`str_replace` при редактировании иногда молча теряет контент** при
   опечатке в имени параметра — проверка `grep`/баланса скобок сразу после
   каждой правки спасла много раз. Для крупных механических правок
   (разбиение файла на части) надёжнее писать Python-скрипт с точным
   подсчётом скобок (учитывающим строковые шаблоны `${...}`), чем
   полагаться на `str_replace`
6. **`internal`-свойство не может использовать `private`-тип.** При выносе
   методов класса в extension-функции (вынужденный приём, раз Kotlin не
   разбивает класс на файлы) видимость приходится поднимать по цепочке —
   если поле стало `internal`, все типы, которые оно использует, тоже
   должны быть minimum `internal`
7. **Сторонние датасеты полезны, но не заменяют реальный захват** — EQ
   Shape, например, подтверждён нашим собственным захватом, но отсутствует
   в стороннем датасете целиком

## Источники данных

- Основной: захват трафика официального Mixtender 2 через Wireshark —
  всё, что подтверждено им, помечено "ПОДТВЕРЖДЕНО реальным захватом" в
  комментариях кода
- Вспомогательный: `muffeeee/midas-pro-series-osc-commands` (GitHub)
- Вспомогательный: `MyronKoch-dev/midas-pro-mcp-server` — MCP-обёртка над
  тем же датасетом muffeeee + отдельный файл на 700 команд внутренних
  FX-параметров (не разбирали)
- Всё, что НЕ из собственного захвата, помечено в коде как "НЕ
  подтверждено реальным захватом"

## Известные ограничения по данным

Нет подтверждённой формулы "сырое значение ручки 0.00-1.00" → точные
единицы, КРОМЕ: порог/атака/релиз компрессора, диапазоны частот EQ по
полосам, WIDTH диапазон EQ (0.1-3.0, линейная интерполяция).

Все графики (COMP/GATE, EQ) — иллюстративные: корректное направление и
форма, но не лабораторно точные.
